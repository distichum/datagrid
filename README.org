#+TITLE: datagrid.el - Emacs Lisp 2d data structure library
#+AUTHOR: Joshua Lambert <jlambert@missouristate.edu>

* Overview
This GNU Emacs package is an Elisp library for two dimensional data. The first dimension is a vector. The second dimension uses a custom data type to hold column data. Datagrids have some similarities to database tables, spreadsheets, and dataframes.

This package is very young and may change often. *It does not provide a buffer user interface* but datagrid-to-org-table makes this possible from Org Mode code blocks.

Datagrid follows the grammar of the R package [[https://dplyr.tidyverse.org/][dplyr]] while fitting Emacs Lisp conventions. Verbs take the datagrid as their first argument and return a new datagrid, so they can be chained with =thread-first=. Most functions accept a column as either a zero-based index or a heading string.

* Installation
** Manually
Add the datagrid directory to your load-path and require datagrid. This also loads datagrid-verbs.el, datagrid-stats.el, and datagrid-join.el. Datagrid requires Emacs 28.1 or later.

#+begin_src emacs-lisp
(add-to-list 'load-path "path/to/datagrid/")
(require 'datagrid)
#+end_src

Reading CSV files needs one more package. =datagrid-from-csv-buffer= and the default parser of =datagrid-from-csv-file= use csv-mode. The pcsv parser of =datagrid-from-csv-file= uses pcsv. csv-mode is on GNU ELPA and pcsv is on MELPA. Each is loaded only when it is used.

* What is a datagrid
A datagrid is a table of data in which every column has the same number of elements. It is a =cl-defstruct= with three slots:

- =columns=: a vector of datagrid-column structs, one per column.
- =row-order=: a vector of row indices that sets the order of rows, or nil for the stored order.
- =col-order=: a vector of column indices that sets the order of columns, or nil for the stored order.

The two order slots let verbs such as =datagrid-sort=, =datagrid-select=, =datagrid-slice=, and =datagrid-filter-by-mask= return a new datagrid that shares its column data with the original. Only the order vectors are new, so these operations stay fast on large tables.

Each datagrid-column holds a heading, a data vector, a level of measurement, and coding information. Create a datagrid with =datagrid-make=:

#+begin_src emacs-lisp
  (datagrid-make
   :columns
   (vector
    (datagrid-column-make :heading "date"
                          :data ["2025-03-31" "2025-04-01"]
                          :lom "nominal")
    (datagrid-column-make :heading "location"
                          :data ["somewhere" "far"]
                          :lom "ordinal"
                          :code '(("somewhere" . 1) ("far" . 2)))))
#+end_src

It evaluates to the following. Read =#s(...)= as a struct with its slots in order. The two trailing nils are the row and column orders.

#+begin_src emacs-lisp
  #s(datagrid
     [#s(datagrid-column "date" ["2025-03-31" "2025-04-01"]
                         "nominal" nil)
      #s(datagrid-column "location" ["somewhere" "far"]
                         "ordinal" (("somewhere" . 1) ("far" . 2)))]
     nil nil)
#+end_src

** Heading
- =datagrid-column-heading (datagrid-column)=: Access the heading of a datagrid column.
** Data
- =datagrid-column-data (datagrid-column)=: Access the data vector of a datagrid column.
  - There must be N elements in each datagrid-column-data slot. In this documentation "data columns" typically means the (datagrid-column-data) slot of a structure.
  - The data slot keeps the stored order and ignores a datagrid's row-order. Use =datagrid-pull (datagrid col)= to get a column's data in the datagrid's row order.
** Coding information
A datagrid-column may hold textual data such as: Strongly disagree, Disagree, Neutral, Agree, Strongly agree. Such data may be ranked from smallest to largest. Coding that data into numbers allows computers to more easily find statistics such as minimum, maximum, and median. The coding data must be provided in an alist such as the following one.

#+begin_src emacs-lisp
  '(("Strongly disagree" . 1)
    ("Disagree"          . 2)
    ("Neutral"           . 3)
    ("Agree"             . 4)
    ("Strongly agree"    . 5))
#+end_src

- =datagrid-column-add-code (datagrid cols code)=: Set the coding for one or more datagrid columns and return a new datagrid. =Cols= can be a column index, a heading string, or a list of them. The alist CODE is put in the code slot of each of those columns. DATAGRID is not modified.
- =datagrid-column-decode (datagrid col &optional default missing)=: Return a vector where each element in the vector has been changed to the appropriate value based on the mapping in the datagrid-column code slot. DEFAULT replaces non-nil values that are not in the alist, and MISSING replaces nil values. Both default to nil. If the code slot is nil, the data slot is returned unchanged.
- =datagrid-column-coerce (datagrid converters)=: Return a datagrid with some columns converted value by value. CONVERTERS is an alist of =(COLS . FN)=, where COLS is a column index, a heading string, or a list of them, and FN is called on each value. Converted columns keep their =lom= and =code= slots, but the code alist is not updated. This is the usual way to turn CSV strings into numbers: =(datagrid-column-coerce (datagrid-from-csv-file "data.csv" t) '(("age" . string-to-number)))=.

** Level of measurement
The Level Of Measurement (LOM) may be one of the following:
- nominal
- ordinal
- interval
- ratio
- nil

The levels determine what statistics that datagrid reports return for that column of data: =datagrid-report-nominal=, =datagrid-report-ordinal=, =datagrid-report-interval=, =datagrid-report-ratio=.

(The author recognizes that the reports will not be suitable for all cases and that some people disagree with using the four levels of measurement. Feel free to provide constructive feedback.)

* Create a datagrid
There are a number of ways to create a datagrid.
** From an alist
=datagrid-from-alist (alist &optional headings extend-uneven)=: Create a datagrid from a list of lists. Each list becomes one column. If =headings= is non-nil, the keys of the alist are the heading text and the values of the alist are the data. If =headings= is nil, then the key and value are both considered data. If =extend-uneven= is nil, every column is cut to the length of the shortest list. If it is non-nil, shorter columns are extended with nil to the length of the longest list.

#+begin_src emacs-lisp
  (datagrid-from-alist
   '(("date" . ("2025-03-31" "2025-04-01" "2025-04-02" "2025-04-03"))
     ("location" . ("somewhere" "out" "there" "far"))
     ("precipitation" . (0.5 0 .25 1))
     ("high-temp" . (15 20 32 22)))
   t)
#+end_src

** From vectors
=datagrid-from-vectors (&rest vectors)=: Create a datagrid from vectors. Each vector given as an argument is considered another datagrid column. The first element of each vector is the heading and the rest is the data.

#+begin_src emacs-lisp
  (datagrid-from-vectors
   ["date" "2025-03-31" "2025-04-01" "2025-04-02" "2025-04-03"]
   ["location" "somewhere" "out" "there" "far"]
   ["precipitation" 0.5 0 .25 1]
   ["high-temp" 15 20 32 22])
#+end_src

** From a csv file
=datagrid-from-csv-file (file-path &optional headings parser extend-uneven)=: Create a datagrid from a CSV file. If headings is non-nil, then the first row in the CSV file will be considered headings. If headings is nil, then no headings are added to the datagrid column structures.

PARSER selects how the file is read:
- nil or ='csv-mode= (the default): use Emacs csv-mode. It will interpret a CSV file in whatever way you have csv-mode configured. If your CSV file has fields with line breaks, csv-mode will not process it correctly.
- ='pcsv=: use the pcsv package. It handles fields with line breaks and very large files.

EXTEND-UNEVEN is passed to =datagrid-from-alist= and is only used by the pcsv parser. Both parsers return every value as a string.

#+begin_src emacs-lisp
  (datagrid-from-csv-file "file-path" t)
  (datagrid-from-csv-file "file-path" t 'pcsv)
#+end_src

** From a csv buffer
=datagrid-from-csv-buffer (buffer-or-name &optional headings)=: Create a datagrid from a buffer that holds CSV data. If headings is non-nil, then the first row will be considered headings. This uses csv-mode, so fields with line breaks are not read correctly.

#+begin_src emacs-lisp
  (datagrid-from-csv-buffer "data.csv" t)
#+end_src

** With empty cells
=datagrid-make-empty (col-num row-num &optional init heading-list)=: Create a datagrid with COL-NUM columns and ROW-NUM rows. Every element is INIT, which defaults to nil. HEADING-LIST, if given, must have one heading per column.

#+begin_src emacs-lisp
  (datagrid-make-empty 2 3 0 '("a" "b"))
#+end_src

** From datagrid-column structures
=datagrid-column-make (&key heading data lom code)=: Create a datagrid-column. Every slot is optional.

#+begin_src emacs-lisp
  (datagrid-column-make :heading "rain"
                        :data [0.5 0 0.25 1]
                        :lom "ratio")
#+end_src

=datagrid-make (&key columns row-order col-order)=: Create a datagrid from a vector of datagrid-columns. The columns must all have the same length, or =datagrid-make= signals an error.

#+begin_src emacs-lisp
  (datagrid-make
   :columns (vector (datagrid-column-make :heading "rain"
                                          :data [0.5 0 0.25 1]
                                          :lom "ratio")))
#+end_src

To add a column to an existing datagrid, use =datagrid-add-column=. It fits the new column to the datagrid's row count, padding a short column with nil and truncating a long one.

* Get information from or about datagrids
- =datagridp (datagrid)=: Return t if datagrid is a datagrid, nil if not.
- =datagrid-dimensions (datagrid)=: Return the two dimensions of the DATAGRID in a cons cell. Columns is the car and rows is the cdr.
- =datagrid-get-elt (datagrid column-num row-num)=: Return a value at a specific column and row. COLUMN-NUM can be an index or a heading string.
- =datagrid-pull (datagrid col)=: Return the data vector of column COL in the datagrid's row order. COL can be an index or a heading string. This replaces the obsolete =datagrid-get-col-data=.
- =datagrid-get-row-data (datagrid row-num)=: Return all data from a specific row as a vector. A row is the Nth element of each datagrid-column's data in the datagrid.
- =datagrid-get-headings (datagrid)=: Return a vector of all column headings.
- =datagrid-col-index-by-heading (datagrid heading)=: Return the index number of the datagrid-column structure that has a heading of =heading=, or nil if there is none. Most functions also accept a heading string directly.
- =datagrid-describe (datagrid)=: Print a summary of DATAGRID and its first rows, then return DATAGRID.
* Manipulate datagrids
- =datagrid-head (datagrid &optional column-num row-num)=: Return the first ROW-NUM rows and COLUMN-NUM columns of DATAGRID.
- =datagrid-add-column (datagrid &rest datagrid-columns)=: Add one or more datagrid-column structs to a datagrid.
- =datagrid-add-row (datagrid &rest rows)=: Append one or more rows, each a sequence with one value per logical column. Datagrids are not meant for frequent insertions of row data. Such operations are possible but inefficient.
- =datagrid-add-data (datagrid seqs &optional horizontal)=: Add elements to each datagrid-column. DATAGRID a datagrid structure. SEQS is a sequence of sequences. If HORIZONTAL is nil, then each sub-sequence is one column's data. If non-nil, then each sequence is one row's data. The default is nil. The sequences are extended to keep DATAGRID-COLUMN-DATA lengths equal. The sequences of data to add must be in the same order as the datagrid-columns in DATAGRID.
- =datagrid-remove-column (datagrid &rest cols)=: Return DATAGRID without the columns in COLS. Each of COLS can be an index or a heading string.
- =datagrid-remove-row (datagrid &rest indices)=: Remove the DATAGRID rows at INDICES.
- =datagrid-select (datagrid &rest cols)=: Return a datagrid with only the columns in COLS, in the order given. The result shares column data with DATAGRID.
- =datagrid-slice (datagrid &rest row-indices)=: Return a datagrid with only the rows at ROW-INDICES. The result shares column data with DATAGRID.
- =datagrid-mutate (datagrid new-heading fn &rest source-cols)=: Return a datagrid with a column NEW-HEADING made by calling FN on each row's values from SOURCE-COLS. If a column already has NEW-HEADING, it is replaced and keeps its =lom= and =code= slots, so FN can convert a column in place, for example =(datagrid-mutate dg "age" #'string-to-number "age")=. The code alist is not updated, so its keys may stop matching the converted data.
- =datagrid-rename (datagrid col-or-renames &optional new-heading)=: Return a datagrid with renamed headings. Pass a column and NEW-HEADING to rename one column, or an alist =((OLD . NEW) ...)= to rename several.
- =datagrid-set-headings (datagrid heading-list)=: Return a datagrid whose headings are the strings in HEADING-LIST, in column order.
- =datagrid-set-elt (datagrid column-num row-num value &optional inplace)=: Return a datagrid with VALUE at a specific column and row. DATAGRID is not modified unless INPLACE is non-nil. An in-place change also shows in every datagrid that shares that column's data.
- =datagrid-bind-rows (&rest datagrids)=: Stack DATAGRIDS into one datagrid. Columns are matched by heading, and a column missing from one datagrid gets nil for that datagrid's rows.
- =datagrid-coalesce (datagrid &rest col-groups)=: For each list of columns in COL-GROUPS, fill the first column with the first non-empty value across the list, then drop the other columns in the list.
- =datagrid-rows-patch (dg1 dg2 &key on cols)=: Return DG1 with empty cells filled from the rows of DG2 that have the same key, like dplyr's =rows_patch=. ON is the key column and COLS is an alist =((FILL . SOURCE) ...)=. Both are required. Values that are already present are never overwritten.
- =datagrid-sort (datagrid &rest keys)=: Sort a datagrid by one or more KEYS. Each key is a column reference or a sort spec plist =(:col REF :key FN :lessp PRED :reverse BOOL)=, borrowing the vocabulary of Emacs's own =sort=. The first key is primary; later keys break ties. The sort is stable. See the worked examples in =examples.org=.
- =datagrid-pivot-wider (datagrid headings-from values-from &key id-cols values-fn values-fill)=: Reshape long data to wide, like tidyr's =pivot_wider=. Each distinct value of HEADINGS-FROM becomes a column filled from VALUES-FROM. ID-COLS identify a row and default to every other column. VALUES-FN combines several values that land in one cell. Without it, such a cell holds a list and a warning is shown. VALUES-FILL fills empty cells (default nil).
* Filters and masks
- =datagrid-create-mask (datagrid pred col)=: Create a mask for the DATAGRID column COL, which can be an index or a heading string. It applies the predicate function to data from a datagrid column to create the mask. The mask is a vector where every element is either t or nil.
- =datagrid-filter-by-mask (datagrid mask)=: Use a boolean MASK to filter DATAGRID. The result shares column data with DATAGRID.
- =datagrid-group-by (datagrid col)=: Group data in DATAGRID according to COL. Return a vector with one group per unique value of COL, in first-seen order. Each group is a list =(VALUE COLUMNS)=, where COLUMNS is a vector of that group's column data vectors. This function will be slow for medium to large datasets that have many groupings. Filter the datagrid by what is needed first and then group.
* Joins
The join functions follow dplyr. Each takes two datagrids and a key:
- =:on= is required. It can be an index or heading string present in both datagrids, or a cons =(X . Y)= that names the key in each one.
- =:cols= is a list of DG2 columns to add. It defaults to every DG2 column except the key.
- =:suffix= renames DG2 headings that are already in DG1. It defaults to "_2".

Keys are compared with =equal=, so ="1"= and =1= do not match. Empty keys never match. When DG2 has the same key more than once, the first row wins.

- =datagrid-left-join (dg1 dg2 &key on cols suffix)=: Keep every row of DG1 and add the matching DG2 columns, with nil where there is no match.
- =datagrid-inner-join (dg1 dg2 &key on cols suffix)=: Keep only the rows of DG1 that have a match in DG2.
- =datagrid-full-join (dg1 dg2 &key on cols suffix)=: Keep every row of both datagrids. Rows found only in DG2 are added at the bottom.
- =datagrid-semi-join (dg1 dg2 &key on)=: Keep the rows of DG1 that have a match in DG2, without adding columns.
- =datagrid-anti-join (dg1 dg2 &key on)=: Keep the rows of DG1 that have no match in DG2.

#+begin_src emacs-lisp
  (let ((people (datagrid-from-vectors ["id" 1 2 3] ["name" "Ada" "Bo" "Cy"]))
        (scores (datagrid-from-vectors ["id" 1 3 4] ["score" 90 75 60])))
    (datagrid-to-org-table (datagrid-left-join people scores :on "id")))
#+end_src

#+RESULTS:
| id | name | score |
|----+------+-------|
|  1 | Ada  |    90 |
|  2 | Bo   |       |
|  3 | Cy   |    75 |

* Data analysis
- =datagrid-reduce-vec (datagrid function col &key code convert initial-value)=: Reduce a FUNCTION using DATAGRID data in column COL, which can be an index or a heading string. The reduction starts from INITIAL-VALUE when given, otherwise from the first value, as in =cl-reduce=. As an example, the following code finds the sum of all data values from the column indexed at 2.
  #+begin_src emacs-lisp
    (datagrid-reduce-vec datagrid-example #'+ 2)
  #+end_src
- =datagrid-reduce-vec-calc (datagrid func-abbrev col &key code convert)=: Reduce an Emacs Calc function, FUNC-ABBREV, using DATAGRID data. It operates only on single vector Calc functions. Nil values are dropped, and the result is nil when Calc cannot produce a real number, such as the standard deviation of a single value. Pass =:convert t= when the column holds numeric strings. See the function document string for more details. The following example duplicates the results above.
  #+begin_src emacs-lisp
    (datagrid-reduce-vec-calc datagrid-example "vsum" 2)
  #+end_src
- =datagrid-summarize (datagrid specs &key by)=: Compute several reductions at once and return a datagrid with one column per spec. SPECS is a list of plists, each with =:name=, =:fn=, and =:col=, plus the optional =:code=, =:convert=, =:calc=, and =:initial-value=. =:name= is the heading of the result column. With =:calc t=, =:fn= is a Calc abbreviation. Without BY, the result has one row. BY is a column or a list of columns. With BY, the result has one row per group in first-seen order, and the BY columns come first.
  #+begin_src emacs-lisp
    (datagrid-summarize datagrid-example
                        '((:name "total-rain" :fn + :col "precipitation")
                          (:name "max-temp" :fn "vmax" :col "high-temp"
                                 :calc t))
                        :by "location")
  #+end_src
- =datagrid-summarize-across (datagrid fn &rest cols)=: Return a datagrid with one row per unique combination of values in COLS. Every other column is reduced by calling FN on the list of its values in each group.
- =datagrid-group-modify (datagrid fn &rest key-cols)=: Group the rows of DATAGRID by KEY-COLS, call FN on each group as a datagrid, and stack the datagrids FN returns.
- =datagrid-count (datagrid col &key sort name code)=: Return a two-column datagrid with each unique value of COL and how often it occurs. SORT orders rows by descending count, and NAME is the heading of the count column (default "n").
- =datagrid-distinct (datagrid &rest cols)=: Return DATAGRID without duplicate rows. With COLS, only those columns are compared and kept.
* Statistical functions
Some statistical measures of survey data are not included in Emacs. Therefore, datagrid.el includes the following. In each, COL can be an index or a heading string, and a non-nil CODE decodes the column first.
- =datagrid-column-quartiles (datagrid col &optional code)=: Find the first, second, and third quartile of data in a column. Quartiles use the (n+1)p position with linear interpolation (Hyndman and Fan type 6, as in Minitab, SPSS, and Excel's QUARTILE.EXC), so the second quartile equals the median.
- =datagrid-column-mode (datagrid col &optional code)=: Find the mode, most often occurring item, of a column.
- =datagrid-column-mad (datagrid col &optional code)=: Calculate the median absolute deviation.

For frequencies and unique values, use =datagrid-count= and =datagrid-distinct=, described under Data analysis.

* Reports
The following functions return an opinionated list of statistical measures for each level of measurement. The list starts with the column heading, followed by an alist of measures such as =("vmedian" . 0.375)=. COL can be an index or a heading string. Pass =:convert t= when the column holds numeric strings.

- =datagrid-report-nominal (datagrid col)=
- =datagrid-report-ordinal (datagrid col &key code convert)=
- =datagrid-report-interval (datagrid col &key code convert)=
- =datagrid-report-ratio (datagrid col &key code convert)=

- =datagrid-report-all-lom (datagrid)=: Loop through each datagrid column and create a report based on the level of measurement. Return a list of =(heading . report)= conses. It decodes and converts columns as needed, so it takes no keywords.

* Export a datagrid
- =datagrid-to-org-table (datagrid &key headings hline digits)=: Return a list of rows that becomes an Org table when returned from an Org Mode code block. It takes these keyword options:
  - =:headings=: non-nil (the default) puts the column headings in the first row.
  - =:hline=: non-nil (the default) adds a horizontal rule after the headings. It has no effect without headings.
  - =:digits=: rounds floats to that many decimal places. The default nil leaves them as they are.

  Nil values become empty cells, and a =|= inside a string becomes the Org entity =\vert{}= so it cannot split a cell.
  #+begin_src emacs-lisp
    (datagrid-to-org-table datagrid-example :hline nil :digits 2)
  #+end_src
- =datagrid-to-alist (datagrid &optional headings)=: Return a list with one list per column. If HEADINGS is non-nil, each list starts with its heading.
- =datagrid-to-vec-of-vec (datagrid)=: Return a vector of column data vectors in the datagrid's column and row order.
- =datagrid-to-csv-file (datagrid file-path &optional headings)=: Write DATAGRID to a CSV file. If HEADINGS is non-nil, write a heading row first. The lom and code slots are not saved.
- =datagrid-to-csv-buffer (datagrid buffer-name &optional headings)=: Insert DATAGRID as CSV into a new buffer, display it, and return the buffer.
- =datagrid-to-vtable (datagrid buffer-name &optional headings)=: Display DATAGRID as a vtable in buffer BUFFER-NAME.

* Sequence functions on datagrid columns
You can use any of the sequence functions (=seq-=) to work with datagrid columns. Seq works on the data slot of a datagrid-column. Functions that return a subsequence, such as =seq-take= and =seq-subseq=, return a new datagrid-column with the same heading. Functions such as =seq-map= and =seq-filter= return a list. Use =(seq-into column 'vector)= to get a plain vector.

#+begin_src emacs-lisp
  (let ((column (aref (datagrid-columns datagrid-example) 0)))
    (list (seq-take column 2)
          (seq-contains-p column "2025-04-01")
          (seq-into column 'vector)))
#+end_src

These functions see a column's stored order, not a datagrid's row-order. Use =datagrid-pull= to get the data in row order.

* Changes
** 1.1
- Breaking: =datagrid-summarize= takes one list of spec plists and returns a datagrid instead of an alist. Without =:by=, the result has one row. The new =:by= keyword groups the rows, and the result has one row per group. Calls in the old form, with each spec as a separate argument, signal an error that explains the change. To update a call, wrap its specs in a list:
  #+begin_src emacs-lisp
    ;; Before 1.1
    (datagrid-summarize dg
                        '(:name "total" :fn + :col "v")
                        '(:name "top" :fn max :col "v"))
    ;; Since 1.1
    (datagrid-summarize dg
                        '((:name "total" :fn + :col "v")
                          (:name "top" :fn max :col "v")))
  #+end_src
- The functions listed under Deprecated functions are obsolete. They still work, and byte-compiling a call to one shows a warning.
- New: =datagrid-column-coerce= converts columns value by value, for example from CSV strings to numbers. Converted columns keep their =lom= and =code= slots.
- When =datagrid-mutate= replaces an existing column, the column keeps its =lom= and =code= slots. Before, they were dropped. Code alists are not updated, so their keys may stop matching converted data.
- =datagrid-mutate= signals an error unless NEW-HEADING is a string. Before, a nil heading on a grid without headings replaced the first column.

The version before 1.1 was 0.1. Changes between 0.1 and 1.1 are recorded only in the git history.

* Examples
datagrid.el includes an example datagrid named =datagrid-example=. The file =examples.org= has worked examples of every function, with their results.

#+begin_src emacs-lisp
  (datagrid-head datagrid-example)
  (datagrid-dimensions datagrid-example)
  (datagrid-get-headings datagrid-example)
  (datagrid-pull datagrid-example "location")
  (datagrid-column-decode datagrid-example "location")
  (datagrid-sort datagrid-example "high-temp")

  (datagrid-add-row datagrid-example
                    ["2025-04-04" "far" 2 25 "ugliest"]
                    ["2025-04-05" "farrer" 3 26 "gooder"])

  (let ((col1 (datagrid-column-make
               :heading "low-temp"
               :data [5 0 4 -5]
               :lom "interval"))
        (col2 (datagrid-column-make
               :heading "perception"
               :data ["hot" "hotter" "hottest" "global-warming"]
               :lom "interval"
               :code '(("hot" . 0)
                       ("hotter" . 1)
                       ("hottest" . 2)
                       ("global-warming" . 3)))))
    (datagrid-report-all-lom
     (datagrid-add-column datagrid-example col1 col2)))

Threading functions may make multiple steps more readable. Datagrid verbs take the datagrid first, so they work with =thread-first=.

#+begin_src emacs-lisp
  (let ((mask (datagrid-create-mask datagrid-example
                                    (lambda (x) (> x 20))
                                    "high-temp")))
    (thread-first datagrid-example
                  (datagrid-filter-by-mask mask)
                  (datagrid-select "date" "high-temp")
                  (datagrid-to-org-table)))
#+end_src
